# Состояние проекта

## Утвержденная тема

Разработка информационной системы для подбора экипировки для игроков в падел.

В MVP экипировка ограничена ракетками для падела.

## Проблема

Игроку сложно выбрать подходящую ракетку среди множества моделей и характеристик. Каталог сам по себе не объясняет, как параметры модели соответствуют уровню и стилю пользователя. Система должна объединить проверенные данные, сравнение и объяснимые рекомендации.

## Целевая аудитория

Начинающие и игроки среднего уровня, выбирающие первую или следующую ракетку и желающие быстро сравнить реальные модели и понять причины рекомендации.

## MVP

- главная страница;
- каталог 15–30 реальных моделей;
- карточки ракеток;
- фильтрация;
- сравнение 2–3 моделей;
- короткая анкета;
- rule-based / weighted scoring рекомендации;
- топ подходящих моделей и объяснение причин;
- цены и характеристики вводятся вручную по проверенным источникам;
- тестирование pytest.

Вне MVP: авторизация, кабинет, отзывы, покупки, платежи, автообновление цен, другая экипировка, сложное ML и 3D.

## Технологический стек

Web, Python, FastAPI, SQLite, SQLAlchemy, Jinja2, HTML, CSS, небольшой vanilla JavaScript, pytest.

Стек зафиксирован на КТ-1. React, TypeScript и Node.js не используются, так как для серверного MVP они не нужны.

## Текущая задача

Остановиться после публикации проекта на GitHub. Следующий этап после подтверждения пользователя — при возможности деплой.

## Важные архитектурные решения

- Использовать серверный HTML через Jinja2, чтобы не вводить отдельный frontend-стек.
- Хранить каталог в SQLite через SQLAlchemy.
- Начать с небольшого набора проверенных моделей, не выдумывать характеристики.
- Реализовать рекомендации как объяснимую взвешенную оценку, а не как ML.
- Не переходить к 3D до готового и проверенного MVP.
